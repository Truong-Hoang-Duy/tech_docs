# Git Workflow Rules

> File này quy định cách Claude thao tác với git khi làm việc trên nhánh `dev`. Nếu dùng với Claude Code, có thể đổi tên file này thành `CLAUDE.md` (đặt ở root repo) để tự động được đọc mỗi phiên làm việc.

## 1. Nguyên tắc chung

- **Không tự ý commit.**
- **Không tự ý push.**
- Chỉ thực hiện commit/push khi người dùng **xác nhận rõ ràng** (VD: "commit đi", "ok commit", "push lên đi").
- Nếu không chắc người dùng đã xác nhận hay chưa, hỏi lại trước khi thực hiện.

## 2. Quy tắc viết commit message

- Ngôn ngữ: **Tiếng Anh**.
- Văn phong: **ngắn gọn, xúc tích**, mô tả đúng việc đã làm — không lan man.
- Format bắt buộc:
  - Tính năng mới: `feat: <mô tả việc đã làm>`
  - Sửa lỗi: `fix: <mô tả việc đã làm>`
- Trước khi soạn message, **tham khảo các commit gần nhất** (`git log --oneline -10`) để đồng bộ cú pháp/văn phong với repo hiện tại.

**Ví dụ:**
```
feat: add user authentication with JWT
fix: resolve null pointer on empty cart checkout
```

## 3. Không thêm các nội dung sau

- **Không** thêm dòng `Co-Authored-By: Claude ...` vào commit message.
- **Không** thêm bất kỳ attribution/watermark nào của Claude vào commit message hoặc PR description (VD: "Generated with Claude", "🤖 Generated by...", link tới Claude, v.v.)
- Commit message và PR description chỉ chứa nội dung liên quan đến thay đổi code, không nhắc đến việc AI hỗ trợ thực hiện.

## 4. Quy tắc về nhánh (branch)

- Không được code trên nhánh dev, nếu đang ở nhánh dev thì tạo nhánh mới, chuyển nhánh mới để code, tên nhánh mới ngắn gọn dựa vào feat được mô tả trong tài liệu.
- Nếu nhánh hiện tại **chưa tồn tại** trên `origin` → tạo nhánh mới trên `origin` khi push.
- Nếu nhánh **đã tồn tại** trên `origin` → chỉ thêm commit mới vào nhánh, **không tạo lại** nhánh.

## 5. Quy trình khi được yêu cầu commit

1. Chạy `git log --oneline -10` để tham khảo cú pháp commit trước đó trong repo.
2. Chạy `git status` / `git diff` để xác nhận đúng phạm vi thay đổi sẽ commit.
3. Soạn commit message theo format `feat: ...` hoặc `fix: ...` tương ứng, không có dòng Co-Authored-By hay attribution.
4. Chỉ thực hiện `git commit` khi người dùng đã xác nhận.
5. Chỉ thực hiện `git push` khi người dùng yêu cầu riêng (không tự động push sau khi commit).
6. Kiểm tra nhánh đã có trên `origin` chưa trước khi push để quyết định tạo nhánh mới hay chỉ push commit thêm vào nhánh sẵn có.
